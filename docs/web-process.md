# Proceso de venta y entrega de webs (`/web`)

Proceso real para proyectos de desarrollo web (academias, estudios, marcas personales y pequeños negocios). Fuente de verdad para el copy de `/web` y para no contradecir el flujo comercial.

## 1. Primera llamada

Objetivo: conocer el proyecto, no cerrar precio todavía.

Se habla de:

- La idea y el objetivo de la web
- Expectativas del cliente
- Si ya tiene branding (logo, colores, tipografía, fotos) o hay que crearlo de cero

Duración típica: ~15 minutos (Cal.com intro).

## 2. Prototipo gratuito

Con la información de la llamada se prepara un **prototipo / diseño gratuito** para que el cliente vea la dirección visual.

Si le gusta:

- Se concreta el alcance (número de páginas, secciones, funcionalidades)
- Se da un **precio final negociable** (suele ser un buen precio de mercado)
- Se acuerda la **fecha de entrega**

Si no le gusta o no encaja, no hay compromiso de desarrollo.

## 3. Pagos (al ir adelante)

Si el cliente quiere continuar, la forma de pago es:

| Momento | Porcentaje | Cuándo |
| --- | --- | --- |
| Al firmar / empezar | **50%** | Tras aceptar prototipo, precio y fecha |
| Versión avanzada | **30%** | Cuando puede ver un progreso claro del proyecto |
| Entrega | **20%** | Al entregar el proyecto |

Es decir: **50% al firmar → 30% a mitad (versión avanzada) → 20% a la entrega**.

## 4. Construcción

- Se construye en una **URL de pruebas** que el cliente puede abrir en cualquier momento
- Ve el progreso de forma continua, no solo al final
- En el punto de versión avanzada se cobra el 30%

## 5. Entrega

En la entrega se incluye:

- Entrega del código en el **repositorio propio del cliente**
- Creación de la **base de datos propia del cliente**
- Mejora de **SEO y rendimiento** antes de cerrar
- Entrega del proyecto en producción / listo para publicar

### Soporte post-entrega (incluido)

Durante los **3 días siguientes a la entrega**, soporte activo **gratuito** para:

- Resolver dudas
- Corregir algo que no funcione
- Modificar **pequeños detalles**

Después de esos 3 días, el **mantenimiento tiene coste aparte**.

## Resumen para la web pública

En `/web` conviene mostrar 4 pasos claros (sin saturar):

1. Llamada — idea, expectativas y branding  
2. Prototipo gratis — si encaja, precio negociable + fecha  
3. Construcción — URL de pruebas y pagos 50 / 30 / 20  
4. Entrega — repo, DB, SEO/rendimiento + 3 días de soporte  

Los detalles de porcentajes y soporte de 3 días sí son relevantes para generar confianza; el resto técnico (Search Console, etc.) puede quedar en FAQ o en este documento.
